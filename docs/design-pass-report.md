# 디자인 패스 보고서 (2026-09-21)

시각적인 변경만 했다. `src/core/`, 상태/판정 로직, 한글 문구, `data-*`/id 값은 건드리지 않았다.
`npm test` 240개 전부 통과, `npm run build` 로 `dist/index.html` 단일 파일 생성 확인.

## 방향

클레이모피즘의 **구조**(두꺼운 테두리, 큰 반경, 이중 그림자, 통통 튀는 눌림)만 가져오고,
색은 이 프로젝트의 기존 정체성(크림 배경/오렌지 강조/카피바라 갈색)을 그대로 유지했다.
스킬이 제안한 파란색 팔레트와 구글 폰트(Baloo 2 / Comic Neue)는 채택하지 않았다 — 파란색은
카피바라의 세계관과 어긋나고, 웹폰트는 "외부 네트워크 요청 0개" 규칙에 정면으로 위배되며
애초에 한글도 지원하지 않는다. 시스템 폰트 스택을 그대로 썼다.

## 2. 토큰 — 글자 크기/여백 스케일

`:root` 에 `--fs-12/14/16/20/24/32`, `--sp-4/8/12/16/24/32/48` 을 추가하고 스타일시트
전체에 적용했다. 본문은 16px/line-height 1.5. 아이가 읽는 글자 중 14px 미만이던 것들
(`.quiz-title` 13→14, `.tile em` 11→14, `.pill` 12→14, `.badge` 12→14, `.capy-slot`
숫자 라벨 10→14, `.result-xp`/`.result-badges`/`.records-table`/`.muted` 13→14 등)을
전부 14 이상으로 올렸다. 세로셈 grid 안(캐리 15px, 셀 24px)은 이미 14 이상이라 그대로 뒀다.

색 토큰도 필요한 만큼 추가했다: `--accent-text`, `--bad-text`, `--white`,
`--accent-rgb`/`--ink-rgb`(그림자·링을 `rgba()`로 합성하기 위해), `--track-bg`류,
`--pill-bg`, `--badge-*`, `--locked-*`, `--keypad-active-bg`. 스타일시트 안에 `:root`
밖에 남은 원시 hex는 없다(SVG를 그리는 JS 안의 색은 `capybara.js`가 원래부터 쓰던 방식과
동일해서 손대지 않았다).

## 3. 터치 타깃

44×44px 미만이던 두 곳을 고쳤다: `.pill-button`(기록실 보기)과 `.quiz-exit`(집으로).
둘 다 시각적 크기는 그대로 두고 `::after` 로 투명한 히트 영역만 44px 이상으로 넓혔다
(`position:absolute; inset:50% auto auto 50%; width/height:max(44px,100%)`). 다른 버튼
(`.btn-primary`, `.btn-ghost`, `.tile`, `.keypad button`)은 계산해보니 이미 44px를 넘었다.

## 4. 반응형

미디어 쿼리가 하나도 없던 상태에서 모바일 우선으로 다시 짰다. 375 / 768 / 1024px 를
Playwright로 직접 렌더링해 확인했다.

- 카테고리 타일: 기본(좁은 폰) 1열, `min-width:480px` 부터 2열.
- 문제 화면: `.quiz-board` 래퍼를 새로 두고(마크업 최소 변경) 기본은 세로로 쌓고,
  `min-width:768px` 부터 grid와 keypad를 가로로 나란히 배치.
- 세로셈 grid: `overflow-x:auto` 안전망을 달았지만 실제로는 어느 폭에서도 넘치지 않는다
  (최대 5자리 × 44px+gap ≈ 240px). 375px에서 스크린샷으로 정렬 확인, 768px에서도 그대로
  유지됨을 확인했다.
- 기록실 표: `.records-table-scroll` 래퍼(마크업 최소 변경)로 감싸 혹시 모를 좁은 화면에서
  가로 스크롤만 표에 국한되게 했다.

## 5. 포커스 · 모션 · 아이콘

- 모든 버튼/링크/입력에 `:focus-visible` 링 (3px, offset 2px, `--accent-text` 색)을 추가했다.
- `prefers-reduced-motion: reduce` 에서 모든 애니메이션/트랜지션을 사실상 끄고, 레벨업
  팝(`capy-pop`)만 특별 처리했다 — 애니메이션 대신 카피바라 주위에 고정된 링(`box-shadow`)을
  둘러 "상태가 바뀌었다"는 게 계속 보이게 했다.
- 숫자판의 `←`/`✓` 를 인라인 SVG(백스페이스 화살표 / 체크)로 바꿨다. **`data-key` 값은
  `"←"`/`"✓"` 그대로 유지**했고(테스트·키보드 핸들러가 이 값을 그대로 씀), 버튼 안에 그려지는
  내용과 `aria-label`("지우기"/"확인")만 바꿨다.
- 연속 출석 옆 🔥 를 인라인 SVG 불꽃 아이콘으로 바꿨다(집 화면, 기록실 둘 다). ✨(레벨업
  반짝임)는 명세대로 손대지 않았다.

## 6. 세로셈 grid

입력칸(`.g-input`, `.g-carry`)은 클레이 처리를 하지 않고 테두리(2px)·모서리(8→10px)만
아주 살짝만 키웠다. 버튼/타일/카드/히어로에만 두꺼운 테두리(3px)·큰 반경(16~22px)·이중
그림자(인셋 하이라이트 + 아웃셋 그림자)·바운스 눌림(`cubic-bezier(0.34,1.56,0.64,1)`,
180ms)을 적용했다. 캐리 박스가 자리 위에 오는 정렬, 두 번째 부분곱의 1의 자리가 비는 것,
칸 격자 정렬은 `verticalGrid.js`(로직)와 `.g-row`/`.g-cell` 관련 CSS를 건드리지 않아서
그대로다 — 375px/768px 스크린샷으로 직접 확인했다.

## 명세에 없었지만 내가 판단해서 처리한 것

- **`.btn-primary`(한 판 더 버튼)의 흰 글자 대 주황 배경 대비가 2.39:1로 심각하게
  실패**하고 있었다(명세가 지목한 세 개 목록에는 없었음). 버튼 배경을 밝은 `--accent`
  대신 새 `--accent-text`(#8a4e10)로 바꿔 6.61:1을 확보했다 — "주황을 표면으로 쓰되 텍스트가
  얹히는 표면은 그 텍스트가 읽혀야 한다"는 원칙을 지키려는 선택이다. 대신 활성 입력 링·추천
  타일 테두리처럼 텍스트가 얹히지 않는 곳은 밝은 `--accent` 그대로 뒀다.
- `.pill` 글자(`#7a6a55`, 4.48:1로 근소하게 미달)와 `.explain-note`(`--bad` 텍스트,
  3.43:1)도 명세엔 없었지만 실측에서 발견해 같이 고쳤다.
- 카피바라에게 아주 은은한 유휴 바운스(3.4초 주기, ±3px)를 새로 추가했다 — 명세가
  "카피바라가 계속 bob 한다"고 전제했는데 실제 코드엔 없어서, 클레이 방향에 맞게 최소한으로
  넣고 `prefers-reduced-motion` 에서 바로 끄게 했다.
- 문제 화면에서 `#message`(정답/오답 피드백 문구) 위치를 grid 아래에서 title 아래·grid 위로
  옮겼다 — `.quiz-board`가 grid+keypad를 가로 배치로 묶으면서 message를 그 안에 넣으면
  레이아웃이 어색해져서, 상태 표시줄처럼 위쪽에 고정했다. 동작·테스트에는 영향 없음(단순 DOM
  위치 이동).

## 후속 수정 (같은 날, 코디네이터 검수 반영)

Chrome 에서 768×1024 로 직접 재본 결과, 숫자판이 `.quiz-board`(flex) 안에서
shrink-to-fit 되어 버튼이 40×52px 까지 눌린 문제가 지적됐다 — `#pad`/`.keypad` 가
`width:auto`(또는 `max-width`만 있는) 상태로 flex item 안에 있으면, 브라우저가
grid의 내재 크기(max-content)로 좁혀버려 의도한 240px 에 닿지 못했다. 375px 에서도
같은 문제가 있었다(세로 배치라도 `align-items:center` 이면 폭은 fit-content 로 계산됨).

- `.keypad` 에 `width:240px`(고정, `max-width:100%` 로 극단적으로 좁은 경우만 방어)과
  `flex:0 0 auto` 를 줘서 shrink 되지 않게 했다.
- `.keypad button` 을 `height:52px` 고정 대신 `aspect-ratio:1` + `min-width/min-height:48px` 로
  바꿔, 커진 폭에 맞춰 키가 정사각형으로 자라게 했다(가늘고 긴 대신 통통한 정사각형이
  손끝에 더 잘 잡힌다).
- `.quiz-board #pad` 에 `flex:0 0 auto` 를 (768px 미디어 쿼리 안이 아니라) 항상 적용되게
  옮겼다.

측정 결과:

| 뷰포트 | 배치 | 버튼 크기 |
|---|---|---|
| 375px | 세로(스택) | 74.66 × 74.66px |
| 768px | 가로(나란히) | 74.66 × 74.66px |

44px 최소 기준을 요구했던 명세보다도 넉넉하고, 요청받은 48px 최소치도 여유 있게 넘는다.

**320px 확인** (가장 좁은 실사용 폰, 세 자리 × 한 자리에서 실제 올림수 칸(`p0-k1`)이
나오는 문제로 확인): `document.documentElement.scrollWidth - clientWidth === 0`
(가로 스크롤 없음), `p0-k1`(올림수)과 `p0-c1`(그 올림이 들어가는 곱셈 칸)의 중심 x좌표가
정확히 160.0px 로 소수점까지 일치 — 정렬이 픽셀 단위로 그대로 유지된다. 세로셈 관련
CSS(`.g-*`, `.g-row*`)는 이번 수정에서 한 줄도 건드리지 않았다(diff로 확인) — 정렬은
애초에 깨질 수 없는 변경이었다.

`npm test` 240개 재확인, `npm run build` 재확인.
